# Комплект эксперимента: локальные языковые модели на рабочей станции

Комплект воспроизводит раздел 3 статьи. На выходе — заполненные таблицы 10–12, данные для рисунка 4 и скриншоты для рисунков 2, 3 и 5.

**Время:** загрузка моделей зависит от интернета (~60 ГБ); сами замеры — около 1,5–2 часов, оценка ответов — около часа.

## Что в комплекте
| Файл | Назначение |
|---|---|
| `models.csv` | список 6 моделей (имя; тег Ollama; формат диалога) |
| `01_pull_models.ps1` | загрузка моделей |
| `02_bench.ps1` | технические метрики → `results\tech_summary.csv`, `results\context.csv` |
| `03_quality.ps1` | ответы на 5 задач → папка `answers` |
| `tasks\task1..5.txt` | тексты задач (одинаковые для локальных и облачных моделей) |
| `KRITERII_OCENKI.md` | шкала 0/1/2 и эталоны |
| `results_template.xlsx` | таблица для оценок и технических метрик |

## Подготовка (один раз)
1. Убедитесь, что Ollama запущен (значок в трее) и обновлен: `ollama --version`.
2. Закройте игры, браузер с видео и все, что занимает видеопамять. Закройте LM Studio — он держит модели в памяти параллельно с Ollama.
3. Откройте PowerShell в папке комплекта (Shift + правый клик по папке → «Открыть окно PowerShell здесь»).
4. Разрешите запуск скриптов только для этого окна:
   ```
   Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
   ```
5. Заполните лист «Стенд» в `results_template.xlsx` (версии: `ollama --version`, `nvidia-smi`, «Параметры → Система → О системе»).

## Шаг 1. Загрузка моделей
```
.\01_pull_models.ps1
```
В конце выводится `ollama list` — должны быть все 6 моделей.

## Шаг 2. Технические метрики
```
.\02_bench.ps1
```
Скрипт для каждой модели: выгружает остальные, загружает модель, трижды прогоняет короткий и длинный запросы (температура 0, контекст 8192), снимает видеопамять через `nvidia-smi`, затем подбирает максимальный контекст, при котором модель целиком в видеопамяти. Компьютер во время замера не трогайте.

Отдельную модель можно перезапустить так: `.\02_bench.ps1 -Only Gemma` (результаты пойдут в `results\tech_summary_Gemma.csv`).

**Что получится:** `results\tech_summary.csv` — по строке на модель. Перенесите значения на лист «Технические» (подсказка с именами столбцов — под таблицей).

## Шаг 3. Ответы на задачи
```
.\03_quality.ps1
```
Ответы сохраняются в `answers\<модель>\task1..5.md` и `ALL.md` (все пять подряд — удобно для оценки).

## Шаг 4. Облачные ассистенты
Откройте giga.chat и alice.yandex.ru. **Для каждой задачи — новый чат**, текст из `tasks\taskN.txt` вставляется целиком. Ответы сохраните в `answers\GigaChat_cloud\taskN.md` и `answers\Alice_cloud\taskN.md`. Если этот шаг не получится, пропустите его: строки облачных моделей уберем из таблицы 12.

## Шаг 5. Оценка
Оцените ответы по `KRITERII_OCENKI.md` и заполните желтые ячейки листа «Качество». Для задачи 5 проверьте каждую ссылку и заполните «Ссылок названо» и «Из них вымышленных».

Совет: оценивайте одну задачу у всех моделей подряд, а не одну модель по всем задачам — так шкала держится ровнее.

## Скриншоты для статьи
| Рисунок | Что снять |
|---|---|
| Рис. 2 | giga.chat: запрос «Тема: … Предложи три варианта формулировки цели и задач исследования» и ответ. В кадре видно название сервиса. |
| Рис. 3 | ResearchRabbit: коллекция из 3–5 статей по вашей теме и граф связанных работ (Earlier/Later Work). |
| Рис. 5 | LM Studio: загружена GigaChat 3.1 10B-A1.8B, виден ответ на одну из задач и строка статистики (ток/с). Снимайте отдельно от замеров Ollama. |

Формат — PNG, окно браузера/программы без лишних вкладок, ширина от 1600 px.

## Что прислать обратно
1. `results_template.xlsx` (заполненный).
2. Папку `results` целиком (csv-файлы).
3. Три скриншота.
4. По желанию — папку `answers` (пригодится для цитат в обсуждении).

По этим данным будут заполнены таблицы 10–12, построен рисунок 4 и написана интерпретация в разделе 3.

## Если что-то пошло не так
- **`ollama pull` не находит модель с `hf.co/...`.** Откройте страницу модели на huggingface.co и проверьте название квантования (например, `Q4_K_M`); исправьте тег в `models.csv`.
- **YandexGPT отвечает бессвязно или повторяет запрос.** У модели нестандартный формат диалога; скрипт подает его вручную (`template = yandex`). Если ответы все равно странные, напишите — подберем формат по карточке модели.
- **Gemma 4 26B работает очень медленно.** Это ожидаемо: модель не помещается в 16 ГБ, часть слоев уходит в оперативную память. Именно это и измеряется; доля на GPU видна в `gpu_share_pct`.
- **GPT-OSS 20B и Qwen3.5 выдают длинные рассуждения.** Это режим размышления. В метрики скорости он входит честно (это тоже генерация), в ответах рассуждение сохраняется отдельным свернутым блоком.
- **Ошибка `nvidia-smi` не найден.** Перезагрузите компьютер после установки драйвера или добавьте `C:\Windows\System32` в PATH; без него не будет только столбца пиковой видеопамяти.
- **Скрипт упал на середине.** Перезапустите для оставшихся моделей с `-Only <часть имени>`: результаты такого запуска пишутся в отдельные файлы с суффиксом (например, `tech_summary_Gemma.csv`) и не затирают основные.
